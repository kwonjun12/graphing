How Graphing Works

Overview

Two players — an Attacker and a Defender — take turns writing weights onto the edges of a rectangular graph that connects a start node S to a target node T.

A Turn

  • Pick one unassigned edge on the board.
  • Pick one unused number and assign it to that edge.
  • Turns alternate until every edge has a number.

Path Difficulty

For any path from S to T, its difficulty is the largest weight found along that path — the path is only as easy as its hardest edge.

Bottleneck & Final Difficulty (C)

Look at every possible path from S to T. Each path has its own largest-edge value. The graph's final difficulty C is the smallest of those largest values — the easiest route available, at its hardest point.

Example: if the easiest available route still forces you through an edge weighted 7, then C = 7, even if a harder-looking route exists elsewhere.

Winning

The Attacker wants to maximize C; the Defender wants to minimize C. Once all edges are assigned, C is computed and compared to the map's threshold — above it, Attacker wins; below it, Defender wins; exactly on it is a draw.

Why Rectangular Maps?

Every map is built as an expanded rectangular grid so no single edge can decide the game by itself — bottlenecks emerge from real strategic tension, not from a lone chokepoint.

Inspired by a bottleneck-path problem from a national informatics olympiad; adapted and redesigned for Graphing.
